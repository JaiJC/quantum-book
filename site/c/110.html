Oracle model and query complexity: Deutsch–Jozsa, Bernstein–Vazirani

You are handed a sealed box computing a function fff on nnn-bit strings, promised to be either constant (same output for every input) or balanced (0 for exactly half the inputs). To be certain which, a classical computer may need to ask 2n−1+12^{n-1} + 12n−1+1 questions. A quantum computer needs one. That is the Deutsch–Jozsa algorithm, the first clear quantum speedup. It is also a cautionary tale: a classical computer that is allowed to guess, and be wrong one time in a million, needs only about twenty questions. Separations in this oracle model are real, but you must ask exactly what they are separating.

Bernstein–Vazirani

Now f(x)=s⋅x mod 2f(x) = s\cdot x \bmod 2f(x)=s⋅xmod2 for a hidden string sss. Classically, each query reveals at most one bit of sss, so you need nnn queries, even with randomness. The same circuit, one query, outputs sss exactly, because the Hadamard transform of (−1)s⋅x(-1)^{s\cdot x}(−1)s⋅x is a single spike at sss. Hide 5 (as three bits) and run it. Ethan Bernstein and Umesh Vazirani introduced it in 1993; their recursive version gave the first super-polynomial oracle separation against randomized classical computers.

What oracle separations mean

Query complexity counts calls to a black box and ignores everything else. It allows clean, provable separations, which are otherwise rare in complexity theory. But real problems don’t come in black boxes: someone must build the oracle as a circuit, and if the function is simple enough to write down, a classical computer may exploit its structure directly. Oracle separations show what quantum mechanics can do; whether a real problem benefits is a separate question, asked again in every chapter that follows.
